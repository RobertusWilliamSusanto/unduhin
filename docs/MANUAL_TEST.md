# Manual Verification Checklist / Daftar Uji Manual (`unduhin`)

Use this checklist on a target workstation that has network access, `FFmpeg`, `Deno >= 2.3.0`, and `unduhin[ui]` installed to verify live end-to-end behavior outside mocked unit tests.

Use a public-domain / Creative Commons sample video & audio URL for live tests.

| ID | Area | Command / Action | Expected Result | Pass / Fail | Notes |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **M01** | Doctor diagnostics | Run `unduhin doctor` | Exit code `0` when Required components (Python >= 3.10, `yt-dlp`, `FFmpeg`) are present, even if Recommended YouTube tools (`Deno`, `yt-dlp-ejs`) emit a warning; exit code `3` if any Required tool is missing, with clear OS-specific fix instructions and local package fallback details. | | |
| **M02** | Info inspection | Run `unduhin info "<SAMPLE_URL>"` | Displays metadata table (title, uploader, duration, live status, estimated size, selected format) and exits `0` without creating any media or staging files in `~/Downloads/unduhin` or current working directory. | | |
| **M03** | Dry run | Run `unduhin download "<SAMPLE_URL>" --mode audio --dry-run -o ./tmp-check` | Prints planned target filename cleanly with status `DRY-RUN`; exits `0`; `./tmp-check` contains no downloaded `.mp3`/`.mp4` or `.unduhin-tmp-*` folders. | | |
| **M04** | Live MP3 download | Run `unduhin download "<SAMPLE_URL>" --mode audio --bitrate 192 -o ./tmp-out` | Progress bar completes; valid `.mp3` created in `./tmp-out`; summary table shows `OK` and exits `0`; zero `.unduhin-tmp-*` dirs left behind. | | |
| **M05** | Live MP4 + codec verification | Run `unduhin download "<SAMPLE_URL>" --mode video --max-height 720 -o ./tmp-out` then run `ffprobe -v error -show_entries stream=codec_type,codec_name -of default=nw=1 "<file.mp4>"` | Valid `.mp4` created (`<= 720p`); `ffprobe` shows `h264` + `aac` (or displays clear codec-fallback warning if upstream lacks H.264/AAC); zero staging folders left behind. | | |
| **M06** | Playlist bounds & non-playlist rejection | Run `unduhin download "<PLAYLIST_URL>" --mode audio -o ./tmp-pl` (omitting `--playlist`), then re-run with `--playlist --max-items 3 -o ./tmp-pl` | Omitting `--playlist` rejects safely with exit code `2` and creates no media files. With `--playlist --max-items 3`, processes at most 3 items using one playlist extraction call, prints truncation notice if larger, displays summary counts, cleans `.unduhin-tmp-*`, and exits `0` (or `1` if an entry is unavailable). | | |
| **M07** | Batch fail-fast on invalid line | Create `bad_batch.txt` with 1 valid `https://` URL on line 1 and `file:///etc/passwd` on line 2; run `unduhin download --batch bad_batch.txt -o ./tmp-batch` | Exits immediately with code `2`, prints localized error naming **line 2**, and leaves `./tmp-batch` untouched (line 1 is **not** downloaded). | | |
| **M08** | Ctrl+C interrupt cleanup | Start `unduhin download "<LONGER_URL>" --mode video -o ./tmp-cancel` and press `Ctrl+C` while downloading | Exits cleanly with code `130` and interrupted banner; inspect `./tmp-cancel` to verify **zero** `.unduhin-tmp-*` folders and **zero** `.part` files remain. | | |
| **M09** | Web UI: Light / Dark theme & download | Run `unduhin ui -o ./tmp-ui --port 7860`; open `http://127.0.0.1:7860` in a browser | Verify UI listens only on `127.0.0.1`; switch `System` / `Light` / `Dark` and refresh page to confirm `localStorage` persistence; verify borders, labels, and keyboard `Tab` focus outlines are clear; switch `EN` <-> `ID`; run one MP3 or MP4 download and confirm filename appears in Result summary without traceback or internal staging path. | | |
| **M10** | Web UI: Cooperative Cancel | Paste `<LONGER_URL>`, click **Download**, wait until status shows `DOWNLOADING:`, then click **Cancel** | Status updates to `CANCELLED:`, worker stops promptly, and `./tmp-ui` contains **zero** `.unduhin-tmp-*` or `.part` files. | | |
| **M11** | Web UI: Busy port handling | Keep a process bound to `127.0.0.1:7860` and run `unduhin ui --port 7860 --lang en` in another terminal | Exits cleanly with code `1` and localized message mentioning port `7860`, with **zero** Python traceback and **zero** internal staging paths. | | |
| **M12** | Optional live integration pytest | Run `pytest -m "network or integration" -v` | Automated live YouTube info + download tests execute and pass (no skip when `FFmpeg` + `Deno` + internet are present). | | |
| **M13** | Default output folder & env override | Run `unduhin "<SAMPLE_URL>" --mode audio` without `-o`; then repeat with `UNDUHIN_OUTPUT_DIR=./env-out` and with `-o ./cli-out` | First run saves into resolved `~/Downloads/unduhin` and prints that absolute path in the summary; second saves in `./env-out`; third overrides `UNDUHIN_OUTPUT_DIR` with `./cli-out`. | | |
| **M14** | Welcome screen, URL shortcut & mode prompt | Run `unduhin` (no args); run `unduhin "<SAMPLE_URL>"` in an interactive terminal; run `echo "" \| unduhin "<SAMPLE_URL>"` | No args prints short localized welcome with 3 examples and exits `0`; URL without subcommand prompts `1=MP3, 2=MP4`; piped non-TTY run fails cleanly with exit `2` asking for `--mode`. Invalid token `unduhin sembarang` fails as invalid URL (`2`). | | |
| **M15** | Non-UTF-8 console & long path safety | Pipe `unduhin` output on Windows `cp1252` console for a title containing CJK + emoji (`"日本語 🎵 test"`); test download into a ~190-char nested `-o` folder | Console renders replacement chars cleanly without `UnicodeEncodeError`; final written file + `(1)` duplicate keep total path length `<= 240` chars. | | |
| **M16** | Language env override & error output | Run `UNDUHIN_LANG=id unduhin` and `UNDUHIN_LANG=id unduhin --lang en`; inspect failed error output without/with `--verbose` | `UNDUHIN_LANG=id` displays Indonesian text; `--lang en` overrides it to English; normal errors never dump Python tracebacks unless `--verbose` is active. | | |
| **M17** | UI browser DevTools network check | Open `http://127.0.0.1:7860` in Chrome/Firefox/Edge with **DevTools -> Network** open (disable cache), reload `/` and toggle Theme & EN/ID | All HTTP requests go strictly to `127.0.0.1` local assets (`/` and `/assets/*`). Confirm **zero** browser requests leave to `fonts.googleapis.com`, `fonts.gstatic.com`, CDNs, or Hugging Face telemetry endpoints. | | |
